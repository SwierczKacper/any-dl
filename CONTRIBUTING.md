# Contributing

Requests are as welcome as code. If the tool is missing something you need —
however small, however obvious it seems — [open an
issue](https://github.com/SwierczKacper/any-dl/issues/new/choose). You do not
need to suggest how it should work, or be sure it is possible. Describing what
annoyed you is enough to act on.

That includes:

- a flag you expected to exist
- output you find hard to read
- something that works but takes too many steps
- "does it do X?" — if the answer is no, that is a feature request

The [roadmap](ROADMAP.md) lists what is already planned, including which sites
are next. If what you want is on it, saying so still helps — it is how the
order gets decided.

## Reporting a break

No site here offers a public API for this, so the tool depends on endpoints that
change without warning. It has already broken once, when Kick moved VOD ids to
UUIDv7 and the old endpoint stopped recognising links. If it suddenly fails for
you, a report is useful even with no detail beyond the command and its output —
say which site, since they break independently.

## Working on the code

There is no build step and no required dependencies.

```bash
git clone https://github.com/SwierczKacper/any-dl.git
cd any-dl
npm install          # optional bundled ffmpeg
node bin/any-dl.js --help
npm test             # 181 tests, all offline
```

### Adding a site

Sites live one per module in `src/providers/`. A new one means writing that
module and adding it to the registry in `src/providers/index.js` — nothing in
`cli.js` should need to change.

The module exports `key`, `label`, `matchUrl`, `webUrl`, `parseTarget`,
`getVideo`, `getClip`, `getChannelVods` and `getChannelClips`. Whatever object
it returns internally is its own business; the machine-readable output is built
field by field in `src/contract.js`, so a provider fills that shape in and never
changes it.

One optional export exists: `resolvePlayable`. A channel listing has to stay
cheap enough to poll, so if getting a stream URL costs a request per entry, the
listing should leave it out and fill it in here for the single item that was
actually chosen. `src/providers/twitch.js` does exactly that.

Use `src/http.js` rather than `fetch` directly, and reach for `src/browser.js`
only if the site genuinely refuses an ordinary request the way Kick does.

A few conventions worth knowing before opening a pull request:

- **No required dependencies.** The only one is `ffmpeg-static`, and it is
  optional so the tool still works without it. This constraint is the reason the
  project works in places where similar tools do not.
- **Cover new logic with tests.** Anything touching a TTY needs the pty harness
  in `test/prompt.test.js`; the rest is plain unit tests. Tests must stay
  offline — nothing may contact any site. There is a separate live check
  (`npm run smoke`) for that, and a new site belongs in it.
- **Update the README in the same change.** Including the sample output at the
  top, which should be regenerated by actually running the tool rather than
  edited by hand.
- Short-lived branches (`fix/…`, `feat/…`, `docs/…`), squash-merged once CI is
  green on Node 18, 20 and 22.

## Scope

This downloads and saves video. It deliberately does not re-upload, publish or
redistribute anything — see the disclaimer in the README.
